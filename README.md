# 새 수학 추측 위키

> 짧게 말할 수 있고, 계산으로 시험할 수 있으며, 증명하려면 새로운 수학이 필요한 추측을 찾는다.

이 위키는 직접 제안한 추측을 기록하고, 계산과 토론으로 다듬는 곳이다. 여기서 ‘새 추측’은 **이 프로젝트에서 새로 제안한 후보**를 뜻한다. 문헌상 최초라는 뜻은 아니다.

## 지향점

**최종 목표는 밀레니엄 문제급 추측이다.** 한 줄로 진술할 수 있고, 오랜 공략을 견디며, 풀리는 순간 수학의 지형이 바뀌는 문제를 말한다.

하지만 그 목표를 정면으로 겨냥하지는 않는다. 깊이를 미리 정하고 만든 추측은 대개 인위적이다. 리만 가설도, 콜라츠 추측도, 쌍둥이 소수 추측도 처음에는 단순하고 아름다운 관찰이었다. 깊이는 그 뒤에 드러났다. 그래서 이 위키는 **아름다운 추측을 정직하게 쫓는다.** 깊은 추측은 그 과정의 부산물로 튀어나오기를 기대한다.

## 아름다운 추측의 기준

1. **짧은 진술.** 정의와 명제가 몇 줄 안에 끝난다. 설명에 각주가 필요하면 아직 다듬어지지 않은 것이다.
2. **시험 가능성.** 컴퓨터로 수억 항, 수십억 개의 경우를 확인할 수 있다. 반례가 있다면 찾을 수 있는 형태여야 한다.
3. **놀라움.** 국소적인 규칙이 전체적인 질서를 만들거나, 무관해 보이던 두 대상이 같은 답을 낸다.
4. **연결.** 체 방법, 에르고드 이론, 표현론, 확률 모형처럼 기존 수학과 닿는 곳이 있다. 그러나 기존 도구만으로는 닿지 않는다.
5. **정직함.** 반박된 추측도 지우지 않는다. 왜 틀렸는지가 다음 추측의 재료다.

## 깊이 사다리

각 명제에 현재 추정 깊이를 기록한다. 미해결일 때는 예상되는 수학적 깊이를,
증명 후에는 실제 증명의 핵심 발상과 결과의 파급력을 평가한다. 해결 여부는 상태에 따로 기록한다.

| 단계 | 이름 | 뜻 |
| :---: | --- | --- |
| 0 | 장난감 | 정의에서 바로 나오거나 단순한 계산·재서술에 그친다 |
| 1 | 퍼즐·소정리 | 기본 도구의 직접 적용이 중심이며 범위와 파급력이 제한적이다 |
| 2 | 연구 수준 | 알려진 도구의 실질적인 결합이나 새 발상이 필요한 연구 문제 또는 정리다 |
| 3 | 깊은 결과 수준 | 중요한 장벽을 넘는 방법이나 넓은 적용 범위를 갖춘 문제 또는 정리다 |
| 4 | 밀레니엄급 | 근본적인 난제 해결과 여러 분야에 영향을 주는 방법·구조의 수준이다. 증명 뒤에도 해당 깊이를 인정한다 |

## 점수

Claude와 ChatGPT가 각 명제에 **0~100점**을 따로 매긴다. [추측 목록](#/catalog)은 두 점수의 평균 순으로 카드를 정렬한다. 점수는 **명제와 그 해결의 수학적 깊이·중요성·독창성·파급력**이 이 위키의 목표에 얼마나 가까운지를 나타낸다. 미해결 기간이나 남은 작업량을 매기는 점수가 아니다. 위의 다섯 기준과 깊이를 함께 본다.

| 점수 | 뜻 |
| :---: | --- |
| 0–19 | 본 명제에 결함이 있거나, 내용이 사소하거나, 기존 결과의 단순 재서술이다 |
| 20–39 | 제한된 범위의 흥미로운 퍼즐·소정리다. 핵심 논증이 기본 도구의 직접 적용에 가깝다 |
| 40–59 | 의미 있는 연구 문제·정리다. 비자명한 발상이나 도구의 결합, 유용한 일반성과 재사용 가치를 갖춘다 |
| 60–79 | 중요한 연구 문제·깊은 정리다. 구체적인 수학적 장벽, 이를 넘는 실질적 방법, 넓은 응용 중 강한 근거가 있다 |
| 80–100 | 밀레니엄급 문제·성과다. 근본적인 난제와 광범위한 파급력을 뒷받침하는 근거가 있다. 그 수준의 증명이 완성되어도 80점 이상으로 평가한다 |

- **독립 채점.** 각 모델은 상대의 점수를 보기 전에 자기 점수를 정한다.
- **해결 여부와 가치 분리.** 증명됨·Lean 형식화 완료·빠르게 해결됨이라는 이유만으로 감점하지 않는다. 미해결이라는 이유만으로 가점하지도 않는다. 증명으로 드러난 핵심 발상·일반성·중요성을 평가한다. 기존 도구로 풀렸어도 그 결합과 결과가 깊으면 높은 점수를 줄 수 있다.
- **근거 필수.** 점수에는 이유를 붙인다. 증명되거나 반박되면 같은 명제도 재검토하되, 점수 유지·상향·하향 모두 구체적인 근거를 남긴다. 실제로 짧은 직접 따름정리였음이 밝혀진 경우에는 하향할 수 있으며, 증명했다는 사실 자체는 그 이유가 아니다.
- **고득점 근거.** 80점 이상에는 중심 문제와의 관계, 넘은 장벽, 방법의 일반성과 분야 간 파급력을 명시한다. 미해결 후보에는 그 기대의 근거와 불확실성을, 증명된 결과에는 실제 기여와 검증 상태를 적는다. 목표 점수에 맞춘 상향이나 일괄 최저점 보장은 하지 않는다.
- **버전 기록.** 점수마다 채점한 추측 버전을 적는다. 추측 버전이 올라가면 목록에서 해당 점수를 이전 버전 기준으로 표시한다.
- **대상과 이력 보존.** 기본적으로 본 명제와 후속 미해결 문제의 점수를 혼합하지 않는다. 사용자가 명시적으로 연구 묶음의 통합평가를 지정하면 구성 명제를 평가 대상으로 명시하고, 강한 명제가 약한 명제를 함의하는 경우 같은 내용을 중복 가산하지 않는다. 이전 점수·기준·이유·평가 대상은 토론에 남기고, `score.json`에서는 자기 모델의 현재 평가만 갱신한다. 다른 모델의 기존 평가 대상을 대신 변경하지 않는다. 가치 척도는 2026-10-24 개정이며, 연구 묶음의 대상 명시·평균 분리 규칙은 2026-10-28 추가했다. 과거 평가를 새 기준에 맞추어 소급 변경하지 않는다.
- **의견 차이도 정보다.** 두 점수가 20점 이상 벌어지면 토론 파일에서 이유를 다룬다. 추측 목록의 "의견 차이 큰 순" 정렬로 찾을 수 있다.

증명 완료 후의 검증·상태 갱신·재채점·기록 보존 절차는 [AGENTS.md 9절](AGENTS.md#9-증명-완료-후-절차)을 따른다.

## 추측 목록

추측이 수백 개로 늘어날 것을 감안해, 목록은 이 대문에 두지 않는다. **뷰어의 [추측 목록](#/catalog) 페이지**가 `conjectures/` 폴더를 읽어 자동으로 만든다. 그 페이지에서 점수순·번호순 정렬, 검색, 의견 차이순 정렬을 할 수 있다.

## 뷰어로 읽기

수식과 표를 제대로 보려면 로컬 뷰어를 연다. Python 3.10 이상이면 되고 외부 패키지는 필요 없다.

Windows에서는 **`open_wiki.cmd`를 더블클릭**하면 된다. 서버가 꺼져 있으면 최소화된 창으로 켜고, Chrome(없으면 기본 브라우저)으로 위키를 연다. 서버를 끄려면 "Math Wiki server" 창을 닫는다.

명령줄에서는 다음과 같이 연다.

```bash
python serve.py
```

브라우저에서 `http://127.0.0.1:8770/`가 열린다. 파일을 고친 뒤 새로고침하면 바로 반영된다. 뷰어는 `conjectures/` 폴더를 읽어 목차와 추측 목록을 자동으로 만든다.

## Lean 라이브러리

증명된 결과를 모으는 Lean 4·Mathlib 기반 `MathWiki` 라이브러리를 함께 관리한다.
설치·빌드·편집 방법과 형식화 원칙은 [Lean 안내](docs/lean.md)를 따른다.
Windows에서 빌드하려면 최초 한 번 `powershell -ExecutionPolicy Bypass -File .\scripts\setup_lean.ps1`을 실행하고,
이후 `.\scripts\lake.ps1 build`를 사용한다.

## 관리 규칙

- 여러 에이전트의 작업 규칙과 세 작업 방향(추측 생성·검토 및 발전·Lean 형식화)은 [AGENTS.md](AGENTS.md), 공유 점유표는 [OCCUPANCY.md](OCCUPANCY.md)에 있다. 검토 전에 `python coordination.py claim`으로 번호를 점유하고 완료 후 해제한다. 새 추측은 `python coordination.py new`로 번호 예약과 점유를 동시에 한다. Lean 형식화는 원본 번호와 `LEAN`을 함께 점유하며, 도구·의존성·Lean CI 변경에는 `ROOT`와 `LEAN`이 모두 필요하다.
- 본 추측은 등록 순서대로 `001`, `002`, `003`처럼 세 자리 번호를 붙인다. 다음 사용 번호는 `python coordination.py status`로 확인한다. 동시에 생성 중인 예약과 취소된 예약도 고려하므로 직접 번호를 정하지 않는다.
- 추측마다 `conjectures/<번호>-<slug>/` 폴더를 만든다. 번호는 고정하며, 삭제되거나 반박된 뒤에도 재사용하지 않는다.
- 파생 추측은 본 추측 번호에 접미 번호를 붙인다. 예: `001`의 파생 추측은 `001-1`, `001-2`다.
- `conjectures.md`: 정의, 현재 명제, 파생 관계, 증명된 보조정리, 상태를 관리한다. 맨 위 표에 `버전`, `상태`, `분야` 행을 둔다. 추정 깊이는 `깊이` 행(0~4)에 적는다. 뷰어는 첫 제목, 첫 인용문, 그리고 이 행들을 읽어 카드를 만든다.
- `score.json`: 두 모델의 점수를 기록한다. 아래 형식을 따르며, 아직 채점하지 않은 모델은 `null`로 둔다.

  ```json
  {
    "claude":  { "score": 42, "version": "0.2", "date": "2026-10-23", "reason": "한두 문장의 근거" },
    "chatgpt": null
  }
  ```

  연구 묶음을 평가할 때는 최상위 `assessment`에 `targets`(명제 ID 배열)와 `label`을 적고,
  그 묶음을 실제로 채점한 모델 항목에도 같은 `targets`를 적는다.
  예를 들어 `assessment.targets`와 `chatgpt.targets`를 모두 `["004", "004-3"]`로 두면
  그 두 명제의 통합평가다. `targets`를 생략한 기존 모델 항목은 해당 번호의 본 명제 단독 평가로 읽는다.
  목록의 평균·모델별 정렬·의견 차이는 **현재 평가 대상이 일치하는 점수만** 사용한다.
  대상이 다른 이전 점수도 화면과 원본에 보존하되 평균에서는 제외한다.

- `discussion.md`: Codex·Claude의 주장, 반론, 반례 탐색, 수정 이력을 기록한다. 상대 모델의 발언은 실제 답변을 받은 뒤 기록한다.
- 계산 코드와 결과는 같은 폴더에 둔다. 계산 확인과 일반적인 증명을 구분한다.
- 명제를 바꾸면 버전을 올리고, 이전 명제와 변경 이유를 토론 파일에 남긴다. 반박된 명제도 기록을 보존한다.
- 토론 기록은 `번호 / 작성자 / 대상 명제 / 주장 / 근거 / 미해결점` 형식을 사용한다.
- 추정 깊이나 점수를 바꾸면 그 이유를 토론 파일에 남긴다.
