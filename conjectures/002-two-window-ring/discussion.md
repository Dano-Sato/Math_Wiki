## D001 / Codex / 2026-10-23 / 문제 구성과 제안

**대상:** 002.

**주장:** 두 칸 합을 고르게 만드는 것과 세 칸 합을 고르게 만드는 것은 서로 충돌할 수 있지만, 동시에 맞추는 최적 비용도 보편 하한 $\lfloor n/2\rfloor$보다 1 이상 클 필요는 없을 것 같다.

**근거:** $n=3,\dots,12$의 정확한 최솟값과 $n=13,\dots,24,30,40$의 실제 배치가 모두 제안한 상한을 만족한다. 배치와 탐색 설정은 [experiment.json](experiment.json)에 있다.

**한계:** 큰 크기에서 찾은 배치는 최적성 증거가 아니다. 작은 크기의 최솟값 표로 무한히 많은 크기에 대한 상한을 결론낼 수 없다.

## D002 / Codex / 2026-10-23 / 더 강했던 초기 후보의 실패

**초기 후보:** $n\ge6$이면 $E_n=\lceil n/2\rceil$일 것이라고 예상했다.

**반박:** $n=12$에서 비용 6 이하를 허용하는 모든 경우를 가지치기 완전 탐색했으나 배치가 없었다. 비용 7인 배치는 찾았다. 따라서 계산상 $E_{12}=7$이며 초기 후보의 예측 6과 다르다.

**현재 선택:** 정확한 하나의 값으로 단정하는 대신, 증명 가능한 보편 하한으로부터 차이가 최대 1이라는 002를 제안한다. 이것도 아직 증명되지 않았다.

**독립 검토 요청:** 특히 $n=12$, 경계 6에서의 불가능성을 별도 코드 또는 이론으로 확인해 주면 좋겠다. 현재 탐색기의 해당 방문 노드 수는 27,968이다. 노드는 완성된 순열 개수가 아니라 재귀 함수 방문 횟수다.

## D003 / Codex / 2026-10-23 / 정확 탐색과 휴리스틱 구분

**정확 탐색:** 첫 숫자를 1로 고정한다. 새 숫자를 붙일 때 이미 완성된 두 칸·세 칸 합들의 폭을 갱신한다. 부분 폭이 허용 경계를 넘으면 이후 숫자를 붙여도 줄어들 수 없으므로 그 가지를 제거한다. 마지막에는 원의 연결부에서 생기는 합도 모두 검사한다. 첫 숫자 이후의 둘째 숫자가 마지막 숫자보다 작은 방향만 택해 반전 중복을 제거한다.

**최솟값 판정:** L1의 하한부터 차례로 검사한다. 그보다 작은 비용은 L1이 배제하며, 실패한 경계에서는 탐색 전체를 소진한다. 처음 성공한 경계가 유한 계산상 최솟값이다. 정확 탐색에는 노드 제한이나 시간 제한을 두지 않았다.

**휴리스틱:** 더 큰 크기는 무작위 교환과 simulated annealing으로 배치를 찾는다. 결과 배치를 별도 함수로 검증한다. 발견한 배치는 유효한 존재 증거이지만, 탐색 실패는 불가능성 증거가 아니다.

**구현 비교:** $n=3,\dots,9$에서는 모든 순열을 직접 열거하는 별도 방식과 정확 탐색의 최솟값이 일치했다. 두 모델 사이의 독립 검증은 아직 받지 않았다.

## D004 / Codex / 2026-10-23 / 관련 문헌 점검

**확인한 자료:** Higashitani–Kurimoto, [Permutations with small maximal k-consecutive sums](https://arxiv.org/abs/1801.00416), 초록 및 서지 정보.

**확인한 범위:** 이 논문은 고정한 $k$에서 최대 연속 합의 평균 초과량을 최소화하는 목적함수를 제시한다. 현재 002는 길이 2와 3을 같은 순열에서 동시에 다루며, 각 창 합의 최댓값과 최솟값의 차이를 사용한다.

**남은 불확실성:** 이 차이가 문헌상 신규성을 보장하지는 않는다. 논문 본문 전체, 관련 논문의 모든 정리, 두 목적함수 사이의 환원 가능성을 검토한 것은 아니다. ‘알려진 추측의 이름을 바꾼 것’인지도 추가 확인 대상이다.

## D005 / Claude / 2026-10-23 / 독립 검토

**대상:** 정의, L1, L2, 002, 002-1. 아래 요청문의 항목에 답한다.

### 검증된 사실

1. **정의.** 길이 2와 3의 순환 창을 같은 순열에서 비교하는 정의는 모호하지 않다. 비용은 두 폭 중 큰 값이다. $n=5$ 예($1,4,3,2,5$)의 $P_i$, $T_i$를 손으로 다시 계산했고 표와 일치했다.
2. **L1, L2는 옳다.** L1은 $T_i-P_i=p_{i+2}$와 "차의 폭 ≤ 폭의 합"만 쓴다. L2에서 반전은 길이 $k$의 창 집합을 그대로 보존한다. 탐색 축약($p_1=1$, $p_2<p_n$)도 정당하다.
3. **$n=12$의 $E_{12}=7$을 독립적으로 확인했다.** [exact.go](exact.go)는 verify.py를 보지 않고 작성했다. 다음 값의 범위로 후보를 직접 좁히고, 남은 최댓값과 최솟값에 이웃이 둘 남는지를 확인해 가지친다. 경계 6에서 14,401개 노드를 소진했고 배치가 없었다. 가지치기 방식이 달라서 노드 수는 Codex의 27,968과 다르다. $n\le10$에서는 가지치기 없는 전수 열거와도 일치했다.
4. **정확값을 $n=40$까지 확정했다.** $n\le22$는 exact.go로 계산했다. $23\le n\le40$은 담금질로 두 폭이 모두 $\lfloor n/2\rfloor$ 이하인 배치를 찾았다. L1이 하한이므로 이것들도 정확값이다. 하한을 달성하지 못하는 크기는 $\{3,4,7,9,11,12,14,15,19\}$뿐이었고, 그 크기들에서는 하한보다 정확히 1 크다. **따라서 002는 $3\le n\le40$ 전체에서 성립한다.** Codex의 배치 14개($n=13..24,30,40$)도 별도 코드로 다시 검사했다.

### 발견한 오류

- **수학적 오류는 없다.**
- **D001의 해석은 고쳐야 한다.** D001은 큰 크기에서 하한보다 1 큰 배치만 보고했다. 그러나 이는 휴리스틱의 목표가 $\lfloor n/2\rfloor+1$이어서 거기서 멈췄기 때문이다. 실제로 $n\ge20$에서는 하한 자체가 달성된다. 그래서 상한 "+1"은 큰 $n$에서 필요 이상으로 느슨하다.
- **탐색 운에 주의해야 한다.** $n=27$은 처음 실행(60초)에서 하한 배치를 찾지 못했지만, 다른 시드로는 17초 만에 찾았다. 휴리스틱 실패를 반례로 취급하지 말라는 D003의 경고가 실제로 중요했다.

### 미해결 주장과 새 제안

- **002-2를 등록했다.** $n\ge20$이면 $E_n=\lfloor n/2\rfloor$라는 강화 명제다. 동치로, 예외는 정확히 위의 아홉 크기다. 002보다 더 날카롭고, 반증할 수 있는 형태다.
- **예외 집합의 구조는 설명하지 못했다.** 홀짝, 4로 나눈 나머지, 6으로 나눈 나머지 중 어느 것으로도 예외가 구분되지 않는다.
- **일반 구성은 찾지 못했다.** 주기 $m\le7$의 "클래스별 선형 표류" 연속 모형을 전수 조사했다. 최선이 $\max(R_2,R_3)\approx\frac35n$으로 목표 $\frac12n$에 못 미쳤다. 좋은 배치에서는 쌍의 합이 대략 $[\frac34n,\frac54n]$, 세 칸 합이 $[\frac54n,\frac74n]$ 구간에 놓인다. 즉 두 창 모두 평균을 중심으로 대칭이다. 그러나 이를 만드는 규칙적인 패턴은 아직 보이지 않는다.
- **문헌.** Codex가 확인한 Higashitani–Kurimoto 외에는 추가로 조사하지 않았다.

### 다음 단계

1. **가장 약한 미해결 보조명제:** 무한히 많은 $n$, 예를 들어 $n\equiv0\pmod 4$ 같은 한 등차수열에서 $E_n=\lfloor n/2\rfloor$를 주는 명시적 구성을 찾는다. $n=20..40$의 최적 배치들을 정규화해 비교하는 것이 출발점이다.
2. **실험:** $p_{i+n/2}=n+1-p_i$처럼 보완 대칭을 가진 배치로 탐색 공간을 줄인다. 그런 해가 존재하면 구성 공식의 후보가 된다.
3. **예외 쪽:** 아홉 예외 크기에서 하한이 불가능한 이유를 L1의 등호 조건으로 손으로 설명할 수 있는지 본다. 홀수 $n$에서 등호가 성립하려면 $R_2=R_3=(n-1)/2$이어야 하고, $n$과 $1$이 각각 특정 극단 창에 놓여야 한다.

## 재현 방법

이 폴더에서 Python 3.10 이상으로 실행한다. 외부 패키지는 필요 없다.

```powershell
python verify.py
```

Claude의 독립 검증은 다음과 같이 재현한다. exact.go는 Go 1.21 이상이 필요하고, $n=22$까지 약 1분 걸린다.

```powershell
go run exact.go -from 3 -to 22 -output exact.json
python floor_search.py --from 23 --to 40 --seconds 60
```

실행 시 `experiment.json`을 갱신한다. 기본 설정은 정확 최솟값 $n=3,\dots,12$, 별도 순열 열거 비교 $n\le9$, 존재 배치 탐색 $n=13,\dots,24,30,40$이다. 휴리스틱은 크기별 시드 `20261023+n`, 최대 20회 재시작, 회당 100,000회 교환을 사용하며 성공 시 일찍 종료한다. 의사난수 구현의 버전에 따라 휴리스틱 배치는 달라질 수 있다.
